Алгоритм подготовки датасета для построения графа знаний (заполнения памяти LLM-агента) на его основе:
0. Создать директорию с названием данного датасета в "data/qa_datasets"-каталоге.
1. В созданном каталоге (с шага 0) должно быть создано/храниться два скрипты: load_data.py и prep_contexts_df.py.
2. C помощью load_data.py выполнить скачивание/урезание датасета. Полученная версия датасета сохраняется в отдельный подкаталог.
3. С помощью prep_context_df.py создать csv-файл, где должны хранится уникальные контексты из полученной версии датасета (с шага 2); csv-файл должен состоять из трёх колонок: "context" - текст на естественном языке, "title" - заголовок контекста (если есть, инчае None), qa_idx - индексы question/answer-пар в полученной версии датасета, к которым относится данный контекст и cntx_idx - идентификатор данного контекста.
4. В notebooks/kg_building/create/create_kg.py добавить функцию для загрузки списка контекстов из соответствующего relevant_contexts.csv-файла. Реализованную функцию добавить в CUSTOM_LOAD_FUNCS-словарь (в том же create_kg-скрипте).

Алгоритм запуска построения графа знаний (необходимые скрипты находятся в "notebooks/kg_building/create"-каталоге):
0. Указать значения гиперпараметров построения графа в kgconn_params-, kgenv_params- и kghyperp_params-yaml файлах
1. Выполнить sh-скрипт init_graph c указанием в качестве параметров названия датасета, на основе которого будет строить граф и название графа знаний, которые были ранее указаны в kghyperp yaml-файле. Будет создана отдельная директория для хранения структур данных графа, а также подняты docker-контейеры с примонтированными каталогами.
2. Если используются LLM-модели из ollama, то необходимо поднять соответсвующий контейнер вручную с использованием .env-файла из созданного каталога, врамках шага #1, с графов.
3. Подключиться к созданному workspace-контейнеру для данного графа через интерактивную консоль.
4. С помощью notebooks/download_models скачать необходимую embedder-модель (если её ещё нет) и сохранить в models-каталог (от корневой директории).
5. Обновить cron-задачу, шаблон которой указан в notebooks/kg_building/cron_buildgraph.txt
6. Поставить cron-задачу, подготовленную в рамках шага #5, в очередь  с помщью cron. В поредке очереди, поставленная задача по построению графа знаний будет поставлена на выполнение.
7. В результате некоторого ожидания граф знаний (память LLM-агента) будет построена
