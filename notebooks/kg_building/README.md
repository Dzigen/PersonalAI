## Построение графа знаний - инструкция

### Подготовка датасета

1. **Создайте папку датасета.** В каталоге `data/qa_datasets/` создайте директорию с именем вашего датасета (например, `my_dataset`).
2. **Добавьте скрипты подготовки.** Внутри папки датасета поместите два скрипта: `load_data.py` (для загрузки/обработки исходного датасета) и `prep_contexts_df.py` (для формирования файлов контекстов). Реализуйте их согласно специфике вашего датасета. Может быть такое, что датасет у вас уже есть и его загружать не требуется. В этом случае просто приведите его к нужному формату 
(описан ниже) с помощью `prep_contexts_df.py`.
3. **Получите обработанный датасет.** Запустите скрипт `load_data.py` - он должен скачать или подготовить сокращённую версию исходных данных и сохранить результат (например, в подпапку внутри директории датасета). Затем выполните `prep_contexts_df.py` для генерации CSV-файла с уникальными контекстами (назовите выходной файл `relevant_contexts.csv`). В CSV должны быть колонки: context (текст контекста), title (заголовок или None), qa_idx (индексы Q/A пар, к которым относится данный контекст) и cntx_idx (уникальный идентификатор контекста). Например, содержимое `relevant_contexts.csv` может быть:
    ```
    context,title,qa_idx,cntx_idx
    "Ползователь хочет стать ...",None,[0],1111
    "У пользователя есть ...",None,"[1, 2]",1112
    ```
4. **Добавьте функцию загрузки контекстов.** Откройте файл `kg_building/create/create_kg.py` и добавьте функцию для вашего датасета по аналогии с уже существующими. Эта функция должна читать `relevant_contexts.csv` вашего датасета и возвращать список из кортежей (text, time, properties) для каждого контекста (в properties можно положить необходимую мета-информацию). Вставьте её в словарь `CUSTOM_LOAD_FUNCS` под ключом, совпадающим с именем вашего датасета (переменная `DATASET_NAME` в `kghyperp_params.yaml`).
  
### Сборка Docker-образа рабочего окружения
1. **Подготовьте Docker.** Убедитесь, что Docker установлен и запущен на вашей машине (процесс построения графа выполняется в Docker-контейнере).
2. **Соберите образ workspace.** В проекте предусмотрен Dockerfile для окружения построения графа знаний. Выполните команду сборки из `deployment/`:
    ```
    docker build --no-cache -t workspace:v5 -f workspace.Dockerfile .
    ```
    Эта команда создаст локальный образ workspace:v5 (название образа, указанное в `docker-compose.yaml` файле), используемый в Docker Compose.
    - Примечание: если на вашей машине нет GPU, закомментируйте строчки, требующие использование видеокарты:
        ```
        # devices:
        #   - driver: nvidia
        #     device_ids: ['0']
        #     capabilities: [gpu]
        ```
    - Примечание: в процессе сборки образа может возникнуть ошибка вида `zlib.error: Error -3 while decompressing data: invalid distance too far back`, связанная с установкой pydantic/pydantic_core. Решение - скорректировать версии: в файле `deployment/requirements.txt` указать `pydantic>=2.12.2,<3` и `pydantic_core!=2.41.3`. Убедитесь, что используете обновлённый файл зависимостей (это должно предотвратить ошибку). При необходимости обновите версии pydantic вручную в требованиях.
    - Примечание: возможна ситуация, при которой либо на вашей машине менее 8 ядер cpu, либо в ресурсах самого Docker выделено менее 8 CPUs. В этом случае замените в `docker-compose.yaml` значение cpu на подходящее вам (4-х ядер должно быть достаточно).
    - Примечание: надежнее устанавливать зависимости в отдельное виртуальное окружение (это необязательно, но позволит сделать процесс стабильнее). Для этого в `workspace.Dockerfile` после `RUN python3 --version` добавьте строки:
        ```
        RUN python3 -m venv /opt/venv
        ENV PATH="/opt/venv/bin:$PATH"
        ```
3. **Проверьте образ.** После успешной сборки убедитесь, что образ workspace:v5 появился (например, командой `docker images | grep workspace`).
  
### Инициализация графа знаний
1. **Настройте параметры графа.** Перед запуском процесса убедитесь, что заданы все необходимые настройки в yaml-файлах (в директории `kg_building/create/`):
    - `kg_building/create/kgconn_params.yaml` - параметры подключения (например, настройки баз данных для графа).
    - `kg_building/create/kgenv_params.yaml` - параметры окружения (пути к директориям, именование контейнеров и т.д.).
    - `kg_building/create/kghyperp_params.yaml` - гиперпараметры построения графа (в том числе `DATASET_NAME` и `KNOWLEDGE_GRAPH_NAME` - название датасета и желаемое имя графа знаний). Здесь обратите также внимание на конфигурацию агента. В частности проверяйте, что стратегрия генерации соответствует выбранному агенту. Например, если использовать в качестве вендора `openai`, то нужно убрать параметр `top_k` и положить `top_p=1e-12` (если важно чтобы `top_p` был равен 0).
2. **Запустите инициализацию графа.** Выполните скрипт `init_graph.sh`, передав два параметра: имя датасета и имя графа знаний (точно как указано в yaml-файле гиперпараметров). Например:
    ```
    cd kg_building/
    bash init_graph.sh my_dataset my_knowledge_graph
    ```
     - Примечание: если ранее вы создавали виртуальное окружение для установки библиотек, то в `init_graph.sh` замените `PYTHON_CMD=/usr/bin/python3` на `PYTHON_CMD=/opt/venv/bin/python`.
     - Примечание: при выполнении скрипта могут возникнуть проблемы с пользователем, в этом случае можете просто указать `USERNAME=root`.
     - Примечание: скрипт `init_graph.sh` внутри запускает выполнение нескольких питоновских скриптов. В частности он запускает `prepare_kg_config.py` из директории `create/`. В этом скрипте инициализируется конфигурация эмбеддера, в которой по умолчанию в качестве девайса используется gpu. Поэтому если у вас нет соответствующего ресурса, то в `EmbedderModelConfig()` нужно добавить: `device='cpu'.

    Скрипт `init_graph.sh` выполнит следующие действия:
    - Создаст директорию `data/knowledge_graphs/<имя датасета>/<имя графа>/` для хранения данных графа (структура папок, файлы настроек и пр.).
    - Запустит временный Docker-контейнер на основе образа workspace для начальной инициализации (смонтировав необходимые каталоги) и сгенерирует файл переменных окружения `.env` внутри созданной директории графа.
    - Остановит временный контейнер и развернёт основной контейнер workspace для вашего графа знаний, используя сгенерированный `.env`. Этот контейнер автоматически поднимет необходимые сервисы (например, базы данных Neo4j, Qdrant, OpenSearch и др., согласно конфигурации docker-compose). Также внутри контейнера будет запущена служба cron (необходимая для планирования задачи построения графа).
3. **(Опционально) Запустите Ollama-агент.** Если в конфигурации графа предусмотрено использование LLM-модели через Ollama (сервис ollama_agent в docker-compose), поднимите этот контейнер отдельно. Например:
    ```
    docker compose --env-file data/knowledge_graphs/<dataset>/<graph>/.env -f kg_building/docker-compose.yaml up -d ollama_agent
    ```
    По умолчанию Ollama отключён (в docker-compose.yaml он закомментирован в depends_on), и этот шаг не требуется, если вы не используете Ollama-модели.
  
### Построение графа знаний (выполнение алгоритма)
1. **Подключение к контейнеру.** Подключитесь к созданному workspace-контейнеру для данного графа через интерактивную консоль. Пример команды:
    ```
    docker exec -it -u root <ID контейнера> bash
    ```
2. **Подготовьте модель эмбеддингов.** Перед запуском алгоритма убедитесь, что необходимая модель для эмбеддингов доступна в системе. Если модель не скачана, в контейнере workspace выполните скрипт загрузки или поместите модель вручную. Например, можно воспользоваться скриптом из `notebooks/download_models` (если такой присутствует) или загрузить модель вручную в каталог `data/models`. Пример команды:
    ```
    python e5_large.py
    ```
3. **Запустите процесс построения.** Построение графа выполняется внутри Docker-контейнера workspace, запущенного для вашего графа. Существует два подхода:
    - Непосредственный запуск: выполните команду внутри контейнера, которая стартует сборку графа знаний сразу. Например:
        ```
        cd ./kg_building/create/
        bash ./crontab_job.sh <GRAPH_NAME> <DATASET_NAME>
        ```
        Эта команда напрямую запускает скрипт построения графа (`build_graph.sh` через cron-обёртку) внутри контейнера. При выполнении скрипта внутри директории графа (`data/knowledge_graphs/<dataset>/<graph>/`) будут появляться файлы `create_log.txt` и `health_log.txt` - в них можно отслеживать прогресс выполнения. Если вы ранее создавали виртуальное окружение, то перед запуском команды выше в файле `build_graph.sh` надо заменить `PYTHON_CMD=/usr/bin/python3` на `PYTHON_CMD=/opt/venv/bin/python`.
    - Запуск по cron (отложенный или плановый): вы можете добавить задачу на построение в планировщик cron внутри контейнера, вместо ручного запуска. Для этого скопируйте шаблон задания в crontab контейнера. Например, чтобы поставить ежеминтуный запуск, можно в контейнере выполнить crontab -e и добавить строку:
        ```
        * * * * * bash /home/workspace/notebooks/kg_building/crontab_job.sh <GRAPH_NAME> <DATASET_NAME> >> /home/workspace/notebooks/kg_building/crontab_log.txt 2>&1
        ```
4. **Дождитесь завершения.** Процесс построения графа знаний может занять продолжительное время (в зависимости от размера датасета и настроек модели). По завершении вы увидите в логах сообщение об успешном окончании ("############ DONE ############"), а в папке графа знаний появится итоговый файл с накопленными триплетами (например, `extracted_triplets.pkl`). Граф знаний построен и сохранён в директории `data/knowledge_graphs/<dataset>/<graph>/` (а данные баз знаний - в смонтированных томах, например в personalai_volumes для Neo4j, Qdrant и т.д.).

### Запуск среды с готовым графом знаний
1. **Поднимите контейнер с графом (если он не запущен).** После построения графа вы можете оставить контейнер запущенным для дальнейшей работы или остановить его. Если контейнер был остановлен, для повторного запуска используйте Docker Compose вместе с файлом переменных окружения, созданным для этого графа. Например:
    ```
    docker compose --env-file data/knowledge_graphs/<dataset>/<graph>/.env -f kg_building/docker-compose.yaml up -d workspace
    ```
    Это создаст (или запустит) контейнер workspace с уже построенным графом, смонтировав все нужные данные.
2. **Подключитесь к рабочему контейнеру.** Чтобы выполнить действия внутри окружения, подключитесь к контейнеру через терминал. Используйте команду:
    ```
    docker exec -it -u root <ID контейнера> bash
    ```
    Теперь вы находитесь внутри контейнера, где установлены все зависимости и доступен построенный граф знаний. Можно запускать нужные скрипты, проводить анализ или интегрировать граф в работу LLM-агента. Если в графе знаний используются сервисы (БД или векторные хранилища), они уже запущены в связанных контейнерах.
3. **Готово.** Окружение с графом знаний запущено и готово к использованию. Когда контейнеры станут не нужны, остановите их, например, командой `docker compose --env-file ... down` или используя скрипт `rm_containers.sh` для автоматической остановки связанных контейнеров.
